- (constraint) PRD y baseline son normativos: dos microservicios Spring Boot 3/WebFlux/Reactor, Kafka triaje.eventos, Triage PostgreSQL/R2DBC, Assistant Redis, RAG Spring AI/OpenAI GPT-5.4-mini vía Azure, RF-05 SQL, RF-06 SSE persistente, AKS/Terraform y CI/CD; conservar RN-01 a RN-05 y E1-E6.
- (decision) AD-1 arquitectura hexagonal liviana por servicio con ownership separado; previene dominio acoplado y acceso cruzado a datos.
- (decision) AD-2 Triage usa transacción PostgreSQL reactiva con transactional outbox para auditoría, alertas y eventos; Kafka entrega al menos una vez, consumidores idempotentes por eventId y versionado monotónico por paciente; previene pérdida entre commit y publicación sin 2PC.
- (decision) AD-3 contrato de evento JSON versionado schemaVersion=1, UUID eventId, aggregateId, aggregateVersion, eventType, occurredAt UTC, payload minimizado; partition key patientId mantiene orden por agregado.
- (decision) AD-4 Assistant usa Redis como proyección de paciente activo con control de eventId/version por paciente y actualización atómica; ALTA elimina/inactiva, consulta y escalamiento no alteran conteo; reconstrucción desde Kafka.
- (decision) AD-5 RF-05 usa UTC, [desde,hasta), bucket por hora de registro y métricas de espera solo para pacientes con primera entrada EN_CONSULTA; promedio/p95 sobre duración en minutos calculados en PostgreSQL; registrados incluye todos.
- (decision) AD-6 RF-06 mantiene alerta persistida atómicamente con flag/auditoría/outbox; SSE y GET histórico son vistas de la misma fuente; Last-Event-ID habilita replay y clientes deduplican por alertId; no promete transporte exactly-once.
- (decision) AD-7 RAG: Spring AI 1.0.x y SimpleVectorStore en memoria, corpus versionado empaquetado; Azure OpenAI text-embedding-3-small para embeddings y gpt-5.4-mini para redacción; umbral de similitud configurable calibrado con corpus de prueba, cita ensamblada desde metadata y abstención fija pre-LLM cuando no hay hit.
- (decision) AD-8 endpoints externos autenticados por API key independiente por servicio en header; secretos cloud en Key Vault accedido con AKS Workload Identity; TLS en ingress y APIs clínicas nunca registradas en logs.
- (question) Se requiere suscripción Azure con cuota AKS/Foundry, región disponible para ambos modelos y DNS/certificado o mecanismo de TLS/URL pública; sin esos insumos no puede garantizarse despliegue público.
- (assumption) La ventana de reconstrucción Redis se garantiza con retención del topic mayor que la edad máxima de datos/proyección del demo; fijar retención mínima 7 días y documentar reset/replay operacional.
- (event) Decisiones de diseño registradas para solución global; se redacta un único documento de diseño en lugar de un segundo architecture spine por solicitud de alcance.
